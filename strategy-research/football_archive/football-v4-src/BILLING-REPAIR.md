# Hub review repairs

1. Recovery separates structural/cumulative ledger validation from the stale account floor. An approved recovery bound to the stopped ledger hash clears the old epoch, adopts the approved current baseline, and enforces the floor and all ceilings before any paid reservation. No debit is erased.
2. Runtime is an absolute, root-keyed global store outside every checkout. A second clone uses the same ledger; a separate central marker refuses reinitialization after ledger or root-folder deletion. Fresh account baselines must be at or below the hub-approved max_baseline_used and within its billing period. Execution from the live checkout or with any alternate runtime is refused.
3. Independent actual play can only exclude a scheduled-pregame quote or certify one already eligible. It cannot admit a decision after the provider or independent scheduled kickoff.
4. Paid approvals bind CSV digest, request-set digest, budget, root, current full commit, comment URL and exact APPROVED body. Live execution verifies the comment through authenticated GitHub before reading the Odds API key. Owner evidence is supplied only after that hub comment.
5. --accept-missing is offline and requires a hub-approved comment bound to request, root, reason, stopped ledger hash and commit. Only demonstrated excessive snapshot lag, cached 404 or observed uncached 5xx can be accepted. It retains the durable upper-bound reservation and bill, writes a terminal missing receipt, never resends, and requires a fresh approved account epoch before continuation. Overcharges, unreadable billing, unknown failures and identity mismatches cannot use this path. Coverage retains all intended missing instruments and reasons; the handoff retains missing calls without prices.
6. Runtime ledgers/receipts and local venvs are gitignored. The published v3 reference is a path-redacted export, with its original reviewed certificate retained. The original local v3 is untouched. V4 inherits this export's path-neutral provenance and records the eligibility amendment explicitly.

Shared usage and counter lag are bounded independently at 100 credits, using cumulative high/low counters and conservative remaining. The vendor client still uses probe-derived A30=5,000. No guarantee is made about provider billing or deletion of every local state record. Max-baseline and billing-period approval prevent a fresh store from silently adopting an already spent or later-period balance.
