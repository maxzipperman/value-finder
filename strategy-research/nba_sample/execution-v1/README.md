## Frozen packet and predecessor

`stage.py` verifies the candidate file hashes and identities, scans exact planned keys across the source's listed raw stores plus live, isolated and global runtime stores, and refuses any paid cache hit. It preserves the explicit historical roots, discovers existing peer/global stores, and includes this checkout’s own raw store only when it exists; a checkout without one adds no phantom path. It freezes that raw-root inventory and the **then-current completed older-stage predecessor** into a new packet with `requests.json`, `request-list.csv`, `manifest.json`, `seed.json`, `cache-reconciliation.json` and `FREEZE.json`. Every ancestor root, ledger hash, terminal status, registration marker, probe debit, reservation and cache identity is checked. The child's carried debit cannot fall below its parent's actual conservative debit. Boolean/negative accounting values, pending/stopped epochs, cycles, duplicate IDs or cache keys, and cumulative use above the 250,000 first-tranche or 400,000 day-one ceiling fail closed.

The immediate predecessor must have `status=older_epoch_complete`. The shared byte-pinned F2 handoff now requires both exact reconciled partial ancestors and a verified full-union proof in every real packet; its final reviewer-pinned verifier/certificate values are intentionally absent until #119 and #121 complete, so preparation currently fails closed. The current F2 halt and the earlier completed pilot are **not eligible N0 predecessors**. A packet prepared against a disposable synthetic or earlier state is never a paid packet. After F2 recovery/continuation, F3a and older acquisition finish, prepare a fresh packet from the final older `spending-ledger.json`, commit it, and obtain current-head review. Any source, raw-store inventory, predecessor or code change alters/invalidates that root.

`execute.py --packet <committed-packet> --root <exact-root> --bundle <frozen-v4-bundle>` verifies offline by default. Its hub-only `--confirm --authorization <approved-json> --key-file <key-file>` path requires the exact packet CSV/request-set/root, 7,540-credit cap and execution commit in an authenticated PR #99 paid-run comment, plus an authenticated `APPROVED account ceiling: max-baseline-used <N>, root <root>` line for the current billing month. Approval, source, packet, ancestor, cache and runtime guards run before loading the key, and the same cache/stop checks run again under the global lock. The free account check precedes any reservation; each paid attempt is durably reserved and marked sent before its sole GET. The existing reserve floor, cumulative ceiling, billing/header and zero-retry stops remain active. A failed or ambiguous response stays pending/stopped. There is no automatic recovery, missing-response acceptance, list regeneration or resend.

After a completed acquisition, the hub must report actual billed and reserved credits, headers, receipt/cache hashes, missing/excluded quotes and coverage.
