# Expanded offline coding evaluation

Protocol fixed before inference, 2026-10-02. Synthetic paper-only fixtures; no real odds, research outcomes, credentials, paid requests, live modules or jobs. Four installed models, same four fresh prompts; direct mode, temperature 0, seed 42, 16K context, 3,500 output tokens, 240-second request timeout. No feedback, retries or selective omission. Record every request, response, completion reason, elapsed time and model identity. One model resident at a time, unloaded after its four requests.

Tasks: (1) two-file code delivery with cross-module import, American odds normalization and expiry selection; (2) regression tests evaluated against a correct oracle and eight independently written mutants; (3) four seeded defects in a synthetic research helper, including temporal leakage and input mutation; (4) structured log extraction, preserving exact facts and ignoring instructions embedded in untrusted records. This last task evaluates instruction handling without granting tools. It does not establish resistance during autonomous tool use.

Acceptance cases are defined in expanded.py before inference. Code executes only in the default filesystem/network sandbox, with an AST import/operation gate and a 15-second whole-candidate execution deadline. Requests are separate from grading. File keys must exactly match the permitted pair; no model-directed filesystem writes or command execution. Generated files represent a patch to synthetic modules, not a production repository patch. Mutation-test results count only if the generated suite accepts the correct implementation. Per-case counts are dependent; report complete tasks, valid-row acceptance separately from invalid-row rejection, false-positive review findings, protocol violations and unfinished attempts.

Harness self-check: correct odds/selection implementations must pass all functional cases; each mutant must fail at least one author-written check. A canonical review/extraction answer validates their scorers. The model-produced test suite must accept the oracle and kill mutants without inspecting implementation names/source. No long-context reliability, repeated-run variance, native tool use, real repository tests or unattended coding capability is established by this protocol.
