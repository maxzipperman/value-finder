# Dashboard content (maintained by the hub)

`evidence.json` is the list the Research screen shows. When research merges, add one entry to the list (the dashboard only displays it and never changes it): `id` (short, unique), `title`, `sport`, `result` (one plain sentence), `record` (for example `"715-555-14"`, or `null`), `win_rate` (a number such as `57.2`, or `null`), `n` (the sample size; a number, or a short phrase when it isn't a count of bets), `p_value` (a number, a short quoted phrase such as `"0.19 (one-sided)"`, or `null`), `clears_bar` (`true` only when the p-value is below the bar in force), `bar` (that bar, as written when it was measured), `source` (the file in the repo the numbers are quoted from), and `date` (`YYYY-MM-DD`). `kind` and `note` are optional. Quote numbers exactly as the source file writes them; an entry without a written p-value gets `clears_bar: false`. Give a Rule B result an `id` with `rule-b` in it (for example `nfl-rule-b-replay-mos`): the line under the Board counts those entries to say whether Rule B clears the bar. Write "college football" in sentences, not "CFB".

Do not put the running count of variants here: the dashboard reads it from the last bold number in the "Variants" bullet of `STATUS.md` every time. `forward_tests.json` holds the words for the four forward tests (the rule in one sentence, when each starts and is decided, and the money gate, `"not chosen"` until the owner chooses one); change its words only when a dated amendment changes the rule. Check both files with `python3 -m json.tool` before committing: a file that doesn't parse is shown on the dashboard as "could not be read".
